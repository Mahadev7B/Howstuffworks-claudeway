## The Rule

Invoke relevant or requested skills BEFORE any response or action — including clarifying questions, exploring codebases, or checking files. If a skill proves unsuitable after invocation, you needn't follow it fully.

Before entering planning mode, invoke the brainstorming skill first if you haven't already.

Then announce "Using [skill] to [purpose]" and follow the skill exactly. If it includes a checklist, create a todo per item.

## Skill Priority

Process skills (brainstorming, systematic-debugging) take precedence and establish the approach, then implementation skills execute it.

## Red Flags

Certain thoughts indicate rationalization — stop and check for applicable skills before proceeding:
- Treating questions as simple when they're actually tasks
- Seeking context before checking for relevant skills
- Exploring files/code before understanding skill-based approaches
- Assuming formal processes are unnecessary

## User Instructions

Direct user requests take precedence over skills, which override default behavior. Only skip skill workflows when explicitly instructed.
